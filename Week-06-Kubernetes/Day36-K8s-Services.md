## 📌 What I Learned Today

### 1. Why Services Exist

Pods have dynamic IPs — every restart = new IP:

```
Pod restarts → new IP → your app can't find it 💀

Solution → Service = stable endpoint
         → fixed ClusterIP + DNS name
         → always routes to healthy pods ✅
```

> 💡 You never talk directly to pods in K8s.
> Always talk to Services — they handle routing automatically!

---

### 2. Service Types

#### ClusterIP (Default)
Internal only — for pod-to-pod communication inside the cluster.
```
Pod A → ClusterIP Service → Pod B
No external access
```

#### NodePort
Exposes service externally on every node's IP at a static port (30000–32767).
```
External → NodeIP:30080 → Service → Pods
```

#### LoadBalancer
Provisions a cloud load balancer (AWS ALB etc.) — used in production.
```
External → Cloud LB → Service → Pods ✅
```

---

### 3. How Services Find Pods — Label Selectors

```yaml
# Pod labels:
labels:
  app: web
  tier: frontend

# Service selector:
selector:
  app: web   ← matches ALL pods with this label automatically
```

Service continuously watches for pods matching its selector — new pods added/removed automatically!

---

### 4. Kubernetes DNS — Service Discovery

Every service gets an automatic DNS name:
```
<service-name>.<namespace>.svc.cluster.local

web-clusterip.default.svc.cluster.local
mysql.default.svc.cluster.local
```

Powered by **CoreDNS** — runs inside `kube-system` namespace.

```
Pod → nslookup web-clusterip → CoreDNS resolves → ClusterIP → Pods
```

> 💡 This is how microservices find each other in K8s — DNS names, not IPs!
> Same as how Docker Compose used service names as hostnames.

---

### 5. Endpoints

K8s automatically creates Endpoints — the list of actual pod IPs behind a service:

```bash
kubectl get endpoints web-clusterip
# 10.244.0.5:80, 10.244.0.6:80, 10.244.0.7:80

# Scale to 5 → endpoints update automatically!
kubectl scale deployment web-app --replicas=5
kubectl get endpoints web-clusterip
# Now shows 5 IPs ✅
```

---

### 6. Port Forwarding

Direct local access to any pod or service — without exposing it externally:

```bash
kubectl port-forward pod/<name> 8080:80      # local:8080 → pod:80
kubectl port-forward service/<name> 8081:80  # local:8081 → service:80
```

> 💡 Port forwarding = best tool for debugging internal services
> without creating NodePort or LoadBalancer!

### Part A — Deployment with Labels

**`deployment.yaml`:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
      tier: frontend
  template:
    metadata:
      labels:
        app: web
        tier: frontend
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
```

```bash
kubectl apply -f deployment.yaml
kubectl get pods --show-labels
```

Observed: `pod-template-hash` auto-generated by K8s on every pod.

---

### Part B — Labels & Selectors

```bash
# Filter by single label
kubectl get pods -l app=web
kubectl get pods -l tier=frontend

# Filter by multiple labels
kubectl get pods -l app=web,tier=frontend

# Wrong label → no match
kubectl get pods -l app=backend
# No resources found
```

**Dynamic label management:**
```bash
# Add label to running pod
kubectl label pod web-app-67d57547d8-6whsl version=v1

# Verify
kubectl get pods --show-labels
kubectl get pods -l version=v1

# Remove label
kubectl label pod web-app-67d57547d8-6whsl version-
```

✅ Labels modified on running pods — K8s resources are highly dynamic!

---

### Part C — ClusterIP Service

**`clusterip-service.yaml`:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-clusterip
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
```

```bash
kubectl apply -f clusterip-service.yaml
kubectl get services
kubectl describe service web-clusterip
kubectl get endpoints web-clusterip
```

**Test internal DNS from inside cluster:**
```bash
kubectl run test-pod --image=busybox --rm -it --restart=Never -- sh
```

Inside pod:
```sh
wget -qO- web-clusterip
wget -qO- web-clusterip.default.svc.cluster.local
exit
```

✅ Service accessible by name — internal DNS working!

### Part D — NodePort Service

**`nodeport-service.yaml`:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-nodeport
spec:
  type: NodePort
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080
```

```bash
kubectl apply -f nodeport-service.yaml
kubectl get services

# Open in browser
minikube service web-nodeport

# Get Minikube IP manually
minikube ip
# Visit: http://192.168.49.2:30080
```

✅ Nginx accessible from browser outside cluster!

### Part E — Port Forwarding

```bash
# Forward specific pod
kubectl port-forward pod/web-app-67d57547d8-5dvcf 8080:80

# Forward service
kubectl port-forward service/web-clusterip 8081:80
```

- `localhost:8080` → pod directly ✅
- `localhost:8081` → via service ✅

> 💡 No external exposure needed — perfect for debugging internal services!

## 💡 Key Concepts I Understood Today

- Services = stable networking layer — pods have dynamic IPs, services don't
- ClusterIP = internal only, NodePort = external access, LoadBalancer = cloud LB
- Labels = K8s organization mechanism — everything uses them for selection
- Services find pods via label selectors — not names or IPs
- Endpoints = actual pod IPs behind a service — auto-updated as pods change
- Kubernetes DNS powered by CoreDNS — every service gets automatic DNS name
- Full DNS format: `service.namespace.svc.cluster.local`
- `port-forward` = best debugging tool — direct local access without exposure
- `kubectl explain` = built-in API docs — use while writing YAML
- `kubectl diff` with no output = cluster already matches YAML (not an error!)
- `favicon.ico 404` in nginx logs = normal browser behavior, not a K8s issue
- `-o wide` = extra columns, `-o yaml` = full state, `-o jsonpath` = extract fields
- `pod-template-hash` = auto-generated label added to every pod by Deployment

## ❌ Mistakes I Made (and Learned From)

| Mistake | Error | What I Learned |
|---------|-------|----------------|
| Used `POD_NAME` literally in kubectl logs | Command failed | Documentation placeholders must be replaced with actual pod name from `kubectl get pods` |
| Thought `kubectl diff` with no output was wrong | No error | No output = cluster already matches YAML. It's a success, not silence |
| Worried about `favicon.ico 404` in logs | Not an error | Browsers auto-request favicon — nginx default has none. Harmless |
